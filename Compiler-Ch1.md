# Compiler Chapter 1 Notes

## 1. Compiler 的作用

Compiler 的主要作用是：

> 將 **source code** 轉換成 **assembly language**，之後再由 **assembler** 將 assembly language 轉換成 machine language。

流程：

Source Code
→ Compiler
→ Assembly Language
→ Assembler
→ Machine Language

講義中將 compiler 對 source program 進行翻譯的過程稱為 **compilation**。

---

## 2. User View of a Compiler

從使用者角度來看：

Programming Language
→ Compiler
→ Machine Language

這是簡化後的 view。

實際上：

Source Code
→ Compiler
→ Assembly Code
→ Assembler
→ Machine Code

所以 compiler 本身主要負責：

Source Code
→ Assembly Code

---

# Front-end and Back-end

## 3. Front-end

Front-end 的工作是：

- 分析 source code
- 建立 compiler 內部的 representation
- 產生 **IR (Intermediate Representation)**

簡化：

Source Code
→ Front-end
→ IR

---

## 4. Back-end

Back-end 的工作是：

- 根據 IR 合成 target program
- 產生 target code，例如 assembly code

簡化：

IR
→ Back-end
→ Target Code (Assembly Code)

因此：

Compiler
= Front-end + Back-end

---

# Machine Code Generated by Compilers

## 5. Pure Machine Code

Pure machine code 的特色：

Compiler 直接針對某個特定 machine 的 **instruction set** 產生 code。

它不假設存在：

- Operating System
- Library routines

因此可以直接針對 CPU / Hardware 產生指令。

概念：

Source Code
→ Compiler
→ Machine-specific Instructions
→ Hardware

常用於：

- Operating System implementation
- Embedded applications

所以 Pure Machine Code 常出現在 **system implementation languages**。

---

## 6. Augmented Machine Code

> 注意：是 **Augmented**，不是 Argumented。

Augmented machine code 是針對一個「被額外功能擴充」的 machine architecture。

除了原本的 machine instructions 之外，還可以使用：

1. Operating System routines
   - System Calls
   - Window APIs

2. Runtime Language Support routines

概念：

Program
→ Machine Instructions
+ OS Routines
+ Runtime Support

相較之下：

Pure Machine Code
→ 不假設 OS / Library 存在

Augmented Machine Code
→ 可以使用 OS / Runtime 提供的功能

---

## 7. Virtual Machine Code

Virtual Machine Code 不是直接給真實 CPU 執行的 machine code。

Compiler 先產生：

**Virtual Machine Instructions**

接著由：

**VM Interpreter**

在真正的平台上執行。

流程：

Source Code
→ Compiler
→ Virtual Machine Code
→ VM Interpreter
→ Real Machine

例如 Java：

Java Source Code
→ Compiler
→ JVM Bytecode
→ JVM
→ Real Machine

### 優點：Portability

同一份 virtual machine code 可以在不同平台執行，只要平台上存在對應的 VM interpreter。

例如：

JVM Bytecode
→ Windows JVM
→ Windows Machine

JVM Bytecode
→ Linux JVM
→ Linux Machine

JVM Bytecode
→ macOS JVM
→ macOS Machine

所以：

> 不同的平台需要不同的 VM Interpreter，但可以使用相同的 Virtual Machine Code。

---

# Bootstrapping

## 8. Bootstrapping

Bootstrapping 的核心概念：

1. Compiler 本身使用「它自己可以編譯的語言」寫成
2. 利用既有的 compiler 去編譯 compiler 自己的 source code

例如：

C Compiler
本身也是用 C 寫的

所以可以：

Existing C Compiler
→ Compile C Compiler Source Code
→ New C Compiler

Bootstrapping 也可以用來協助 compiler 移植到新的 machine architecture。

例如：

x86 Compiler
→ 修改 Code Generator
→ 產生 ARM Code
→ 建立可支援 ARM 的 Compiler

---

# Compiler vs. Interpreter

## 9. Compiler vs. Interpreter

### Compiler

核心概念：

> 先翻譯，再執行。

流程：

Source Program
→ Compiler
→ Target Program
→ Execute

Compiler 有兩個主要 phase：

1. Compilation Phase
2. Execution Phase

---

### Interpreter

核心概念：

> 直接 interpret / execute source program。

簡單理解：

Source Program
→ Interpreter
→ Execute

可以理解成「邊解釋、邊執行」，但實際上的 interpreter 不一定真的逐行直接執行 source code。

---

## 10. Interpreter 的三種執行方式

### Method 1：直接執行 Source Code

Source Code
→ Execute

Examples：

- LISP
- BASIC

---

### Method 2：Source Code → IR → Execute

先將 source code 轉成較有效率的 intermediate representation，再立即執行。

Source Code
→ Intermediate Representation
→ Execute

Examples：

- Perl
- Python
- MATLAB
- Ruby

---

### Method 3：Precompiled Code

先由 compiler 將 source code 編譯成 precompiled code 並存起來。

之後再由 interpreter 執行。

Source Code
→ Compiler
→ Precompiled Code
→ Store
→ Interpreter
→ Execute

注意：

> 這裡的 compiler 是 interpreter system 的一部分。

Example：

- UCSD Pascal

---

# Organization of a Compiler

## 11. Compiler 的兩個主要工作

Compiler 主要分成：

### 1. Analysis of Source Program

例如：

- Scanning
- Parsing

### 2. Synthesis of Target Program

例如：

- Code Generation

---

## 12. Scanner

Scanner 會：

> Character by character 讀取 source program，並將 characters 分組成 tokens。

所以：

Characters
→ Scanner
→ Tokens

例如：

a = b + 10;

可以轉成：

IDENTIFIER(a)
ASSIGN(=)
IDENTIFIER(b)
PLUS(+)
INTEGER(10)

簡單理解：

> Scanner = 辨認單字

---

## 13. Parser

Parser 會拿 Scanner 產生的 tokens，根據 grammar 分析程式結構。

通常會產生：

**AST (Abstract Syntax Tree)**

所以：

Tokens
→ Parser
→ AST

簡單理解：

> Scanner 辨認單字  
> Parser 理解句子結構

Parser 通常根據：

**CFG (Context-Free Grammar)**

進行分析。

---

## 14. Type Checker / Semantic Analyzer

Type Checker 又叫：

**Semantic Analyzer**

它會：

1. 檢查 AST 的 semantics 是否正確
2. 將額外的 semantic information 加到 AST 上

因此輸出叫：

**Decorated AST**

流程：

AST
→ Type Checker
→ Decorated AST

簡單比較：

Parser
→ 檢查 Syntax

Type Checker
→ 檢查 Semantics

例如：

int a;
a = "hello";

Syntax 可能正確，但是 semantic/type 不正確。

---

## 15. Translator

如果 AST node 在 semantic 上是正確的：

Translator 會將：

Decorated AST
→ Intermediate Representation (IR)

所以：

Decorated AST
→ Translator
→ IR

---

## 16. Optimizer

Optimizer 的主要工作：

> Improve IR code's performance.

流程：

IR
→ Optimizer
→ Optimized IR

目的：

- 提升執行效率
- 減少不必要操作
- 降低 overhead

講義中的例子包含：

- Method Inlining
- Loop Fusion
- Eliminating unnecessary Result matrix

---

## 17. Code Generator

Code Generator 的工作：

將：

- IR
或
- AST

轉換成：

**Target Code**

例如：

Assembly Code

流程：

IR
→ Code Generator
→ Target Code

---

# 18. Complete Compiler Pipeline

完整流程：

Source Program
↓
Scanner
↓
Tokens
↓
Parser
↓
AST
↓
Type Checker
↓
Decorated AST
↓
Translator
↓
IR
↓
Optimizer
↓
Optimized IR
↓
Code Generator
↓
Target Code

可以簡化記成：

Scanner
: Characters → Tokens

Parser
: Tokens → AST

Type Checker
: AST → Decorated AST

Translator
: Decorated AST → IR

Optimizer
: IR → Better IR

Code Generator
: IR → Target Code
